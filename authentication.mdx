Every request you make through the Developer Portal must be authenticated using an API key. API keys are passed as Bearer tokens in the `Authorization` header of each HTTP request, giving the platform a way to identify you, enforce your plan's rate limits, and attribute usage to your account. Understanding how to obtain, use, and protect your API keys is the foundation of a secure and reliable integration.

## Getting an API Key

To generate an API key, sign in to the Developer Portal and navigate to **Account → API Keys**. Click **Create New Key**, enter a descriptive name that reflects the key's intended use (for example, `production-backend` or `staging-tests`), and choose the scope for the key. Click **Generate** to create the key.

<Note>
  Your API key is displayed **only once** immediately after creation. Copy it to a secure location — such as a secrets manager or a `.env` file — before closing the dialog. If you lose access to a key, you must revoke it and generate a new one.
</Note>

## Passing Your API Key

Include your API key in the `Authorization` request header using the `Bearer` scheme:

```
Authorization: Bearer {API_KEY}
```

The following examples show how to authenticate a request to the catalog endpoint across common tools and languages.

<CodeGroup>
  ```bash curl
  curl https://api.example.com/v1/catalog \
    -H "Authorization: Bearer YOUR_API_KEY"
  ```

  ```javascript JavaScript
  const response = await fetch("https://api.example.com/v1/catalog", {
    method: "GET",
    headers: {
      "Authorization": "Bearer YOUR_API_KEY",
      "Content-Type": "application/json",
    },
  });

  const data = await response.json();
  console.log(data);
  ```

  ```python Python
  import requests

  url = "https://api.example.com/v1/catalog"
  headers = {
      "Authorization": "Bearer YOUR_API_KEY",
      "Content-Type": "application/json",
  }

  response = requests.get(url, headers=headers)
  data = response.json()
  print(data)
  ```
</CodeGroup>

## API Key Scopes

When you create an API key, you can scope it to control which APIs it can access:

- **All subscribed APIs** — The key can make requests to every API you're currently subscribed to. This is convenient for development and testing environments.
- **Specific APIs** — The key is restricted to one or more APIs you choose. Use scoped keys in production to limit the blast radius of a compromised credential.

You can view and update a key's scope at any time from the **API Keys** page. Narrowing a key's scope does not require generating a new key.

## Handling Unauthenticated Requests

If a request is missing the `Authorization` header, contains a malformed token, or uses a revoked key, the API returns a `401 Unauthorized` response:

```json
{
  "error": "unauthorized",
  "message": "A valid Bearer token is required to access this resource."
}
```

Verify that you're including the `Authorization` header in every request, that the token is prefixed with `Bearer ` (note the trailing space), and that the key has not been revoked in your dashboard.

## Security Best Practices

Protecting your API keys is as important as protecting a password. Follow these practices to keep your integrations secure:

- **Use environment variables.** Never hard-code an API key in source code. Store it in an environment variable (for example, `API_KEY`) and read it at runtime.
- **Never expose keys in client-side code.** Avoid including API keys in frontend JavaScript, mobile app bundles, or any code that is distributed to end users. Route API calls through your own backend instead.
- **Rotate keys regularly.** Generate a new key on a routine schedule — or immediately if you suspect a key has been exposed. Revoke the old key only after the new one is live in your application.
- **Use scoped keys per environment.** Maintain separate keys for development, staging, and production. Scope production keys to only the APIs they need.
- **Revoke unused keys promptly.** Delete any keys that are no longer in use from **Account → API Keys** to reduce your attack surface.

<Warning>
  If you accidentally commit an API key to a public repository or expose it in any client-facing context, revoke it immediately from the **API Keys** dashboard and generate a replacement. Treat any exposed key as compromised.
</Warning>
