Once you have an account, an active API subscription, and an API key in hand, you are ready to make your first live request. This guide walks you through every step — from locating your credentials to reading the response — so you can move from zero to a working integration as quickly as possible. By the end you will have sent a real HTTP request, inspected the JSON response, and understood what each status code means.

<Warning>
  Never hardcode your API key directly in source code that you commit to version control. Use environment variables, a secrets manager, or a `.env` file that is listed in `.gitignore`. Exposed keys can be discovered by automated scanners and abused within minutes.
</Warning>

## Prerequisites

Before you begin, make sure you have completed the following:

- Created a Developer Portal account
- Subscribed to at least one API from the catalog
- Generated an API key (Account → API Keys)

## Send Your First Request

<Steps>
  <Step title="Locate your API key">
    Open the Developer Portal and navigate to **Account → API Keys**. You will see a list of all keys you have generated. Click the copy icon next to the key you want to use. If you have not generated a key yet, click **New API Key**, give it a descriptive name, and copy the value immediately — it will not be shown again in full after you leave the page.
  </Step>

  <Step title="Find the base URL for your API">
    Go to the **Catalog** and open the API you subscribed to. On the API details page you will find a **Base URL** field, for example `https://api.example.com/v1`. Every endpoint you call is appended to this base URL. You can also find the base URL in the API's reference documentation tab.
  </Step>

  <Step title="Construct the request">
    Pass your API key in the `Authorization` header using the **Bearer** scheme:

    ```
    Authorization: Bearer YOUR_API_KEY
    ```

    Replace `YOUR_API_KEY` with the key you copied in step 1. The example endpoint used throughout this guide is:

    ```
    GET https://api.example.com/v1/catalog
    ```

    Choose your preferred language below and substitute your real key before running the code.

    <CodeGroup>
      ```bash curl
      curl -X GET "https://api.example.com/v1/catalog" \
        -H "Authorization: Bearer YOUR_API_KEY" \
        -H "Accept: application/json"
      ```

      ```javascript JavaScript
      const response = await fetch("https://api.example.com/v1/catalog", {
        method: "GET",
        headers: {
          "Authorization": "Bearer YOUR_API_KEY",
          "Accept": "application/json",
        },
      });

      const data = await response.json();
      console.log(data);
      ```

      ```python Python
      import requests

      url = "https://api.example.com/v1/catalog"
      headers = {
          "Authorization": "Bearer YOUR_API_KEY",
          "Accept": "application/json",
      }

      response = requests.get(url, headers=headers)
      data = response.json()
      print(data)
      ```
    </CodeGroup>
  </Step>

  <Step title="Send the request and inspect the response">
    Run the command or script. A successful response returns HTTP `200 OK` and a JSON body. Here is an example of what you might receive from the catalog endpoint:

    ```json
    {
      "status": "success",
      "data": {
        "apis": [
          {
            "id": "weather-v2",
            "name": "Weather API",
            "version": "2.1.0",
            "description": "Real-time and forecast weather data worldwide.",
            "category": "Data & Analytics"
          },
          {
            "id": "geocoding-v1",
            "name": "Geocoding API",
            "version": "1.4.2",
            "description": "Convert addresses to coordinates and vice versa.",
            "category": "Mapping"
          }
        ],
        "total": 2,
        "page": 1
      }
    }
    ```

    Inspect the `status` field and the `data` object to confirm you are receiving the expected payload.
  </Step>

  <Step title="Understand the response status codes">
    The HTTP status code is the fastest way to diagnose what happened with your request. Here is what each common code means in this context:

    | Status Code | Meaning | What to do |
    |-------------|---------|------------|
    | `200 OK` | Request succeeded | Read and use the response body |
    | `401 Unauthorized` | API key is missing or invalid | Re-copy your key from Account → API Keys |
    | `403 Forbidden` | Valid key, but subscription issue | Check your active subscriptions |
    | `429 Too Many Requests` | Rate limit exceeded | Slow down requests; see the rate limits guide |
    | `500 Internal Server Error` | Server-side problem | Retry after a short wait; contact support if it persists |

    <Tip>
      If you receive a `401`, double-check that you included the `Bearer ` prefix (with a space) before your key, and that there are no extra spaces or newline characters in the copied value.
    </Tip>
  </Step>
</Steps>
