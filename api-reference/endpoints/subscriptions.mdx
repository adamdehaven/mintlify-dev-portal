Subscriptions link your account to a specific API and plan, granting access to that API's endpoints up to your plan's rate and quota limits. Use these endpoints to see all your active enrollments, subscribe to a new API on the plan that fits your needs, or cancel a subscription when you no longer need access. Cancellations take effect at the end of your current billing period, so you never lose access mid-cycle.

---

## List Subscriptions

Retrieve all subscriptions associated with your account. Optionally filter by status or by a specific API.

`GET /subscriptions`

<ParamField query="status" type="string">
  Filter subscriptions by their current status. Accepted values are `active`, `cancelled`, and `pending`. Omit this parameter to return subscriptions in all states.
</ParamField>

<ParamField query="api_id" type="string">
  Return only the subscription for a specific API. Use the `id` value from the [Catalog](/api-reference/endpoints/catalog) response.
</ParamField>

<CodeGroup>

```bash cURL
curl --request GET \
  --url "https://api.example.com/v1/subscriptions?status=active" \
  --header "Authorization: Bearer YOUR_API_KEY"
```

</CodeGroup>

### Response

<ResponseField name="id" type="string">
  Unique identifier for the subscription.
</ResponseField>

<ResponseField name="api_id" type="string">
  Identifier of the API this subscription grants access to.
</ResponseField>

<ResponseField name="plan" type="string">
  The plan tier for this subscription: `free`, `basic`, or `pro`.
</ResponseField>

<ResponseField name="status" type="string">
  Current lifecycle status of the subscription: `active`, `cancelled`, or `pending`.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp when the subscription was created.
</ResponseField>

<ResponseField name="current_period_end" type="string">
  ISO 8601 timestamp indicating when the current billing period ends. Active access is guaranteed through this date even after cancellation.
</ResponseField>

```json Example Response
{
  "data": [
    {
      "id": "sub_3F8KqZ01",
      "api_id": "api_pay_01HX9Z",
      "plan": "pro",
      "status": "active",
      "created_at": "2024-03-01T00:00:00Z",
      "current_period_end": "2024-04-01T00:00:00Z"
    },
    {
      "id": "sub_7G2LmB04",
      "api_id": "api_msg_02KY7A",
      "plan": "basic",
      "status": "active",
      "created_at": "2024-02-15T12:00:00Z",
      "current_period_end": "2024-03-15T12:00:00Z"
    }
  ],
  "meta": {
    "total": 2
  }
}
```

## Create a Subscription

Subscribe your account to an API by specifying the API and the plan tier you want. If you already have an active subscription to the same API, upgrade or downgrade by cancelling the existing one first.

`POST /subscriptions`

<ParamField body="api_id" type="string" required>
  The unique identifier of the API you want to subscribe to. Retrieve this from the [Catalog](/api-reference/endpoints/catalog).
</ParamField>

<ParamField body="plan" type="string" required>
  The plan tier to enroll in. Must be one of `free`, `basic`, or `pro`. Plan features and quota limits vary per API — check the catalog entry for details.
</ParamField>

<CodeGroup>

```bash cURL
curl --request POST \
  --url "https://api.example.com/v1/subscriptions" \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "api_id": "api_pay_01HX9Z",
    "plan": "pro"
  }'
```

</CodeGroup>

### Response

Returns the newly created subscription object.

<ResponseField name="id" type="string">
  Unique identifier for the new subscription.
</ResponseField>

<ResponseField name="api_id" type="string">
  Identifier of the subscribed API.
</ResponseField>

<ResponseField name="plan" type="string">
  The enrolled plan tier.
</ResponseField>

<ResponseField name="status" type="string">
  Initial status of the subscription. Will be `active` for free plans and `pending` while payment is being processed for paid plans.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp when the subscription was created.
</ResponseField>

<ResponseField name="current_period_end" type="string">
  ISO 8601 timestamp for the end of the first billing period.
</ResponseField>

```json Example Response
{
  "id": "sub_9H5PrC07",
  "api_id": "api_pay_01HX9Z",
  "plan": "pro",
  "status": "active",
  "created_at": "2024-03-20T14:22:00Z",
  "current_period_end": "2024-04-20T14:22:00Z"
}
```

<Tip>
  After creating a subscription, generate or update an API key to include this `api_id` in its scopes so requests are properly authorized. See the [Accounts & Keys](/api-reference/endpoints/accounts) reference.
</Tip>

## Cancel a Subscription

Cancel an existing subscription. Your access to the API remains active through the end of the current billing period; after that date all requests made using this subscription will be rejected.

`DELETE /subscriptions/{subscription_id}`

<ParamField path="subscription_id" type="string" required>
  The unique identifier of the subscription to cancel. Retrieve active subscription IDs from [List Subscriptions](#list-subscriptions).
</ParamField>

<CodeGroup>

```bash cURL
curl --request DELETE \
  --url "https://api.example.com/v1/subscriptions/sub_3F8KqZ01" \
  --header "Authorization: Bearer YOUR_API_KEY"
```

</CodeGroup>

Returns `204 No Content` on success with an empty response body.

<Note>
  Cancellation is immediate in terms of billing — you will not be charged for the next period — but API access continues until `current_period_end`. To restore access after that date, create a new subscription.
</Note>
